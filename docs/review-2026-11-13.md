## 数据与维护边界

- `content/mods` 只描述解析定位和展示选项，不能作为手写卡牌数值的替代入口。
- `catalog` 保留全部模型；`data` 仅保留通过展示合同与基础本地化检查的模型。缺文本模型进入 `quarantined`，不会生成猜测译文。
- 游戏关系对照实际游戏 DLL 类型表；资源追踪 PCK `.import` / `.remap`。运行时费用和计算变量保留原表达式及出处。
- 命名空间已进入实体关系、查询、公共链接和社区归属。非原版公共 ID 使用 `modId:rawId`；原版在冲突时使用 `sts2:rawId`。唯一旧地址重定向，裸冲突拒绝访问。既有章节/修订 ID 保留，无法证明归属的旧记录归档，独立的新实体不会接收旧混合历史。
- 原版离线数据已确认混合快照：596 个卡牌 ID 等于 Codex v0.109.0 的 595 个加 `DeprecatedCard`，配套文本却不匹配该快照。20 个记录缺少英文标题/描述，其中 `Scare` 在当前游戏 DLL/PCK 已不存在；部分卡池也有错位。当前 PCK 英文/中文 cards 表为 1521/1501 键，旧静态表为 1233/1214 键，同名键分别有 55/74 项变化。`Conflagration` 旧数据还残留已不适用的变量。不能只补新文案就宣称恢复准确；需要单独从同一游戏 DLL/PCK 快照完整重建原版目录，本次没有伪造这一步已完成。
- Bash 既有历史表与编辑性说明保留为 Wiki 内容，不把这些历史叙述伪装成当前 DLL 自动提取的机制事实。
- 不删除社区修订、评论归档或导入快照。本次未对用户默认 D1 数据库或远程数据库执行迁移，也未部署。
