## 修正 static/public 资源不能 JS import 的 enhanced 实现
- 结论：`static` 是 public URL 放置位置，`enhanced` 是构建期源码资源处理，不是二选一；SvelteKit images 文档明确
  `@sveltejs/enhanced-img` 只能优化构建期位于本机、可被 import 的文件，动态/CMS/CDN 图走另一类方案。
- Vite 8 报错 `/static/images/...?enhanced=true`：publicDir 资源不能从 JS import；提示里的 `?url&enhanced=true`
  只是取 public URL 字符串，不会产出 `Picture` 对象或 `<picture>`，不能用于 `src={picture}` 的动态映射。
- `static/mods` 由 `virtual:mods` 扫描成 `/mods/...` 运行时 URL，卡面图 `card.image` 与 mod 自定义 `cardFrame`
  继续普通 `<img>` / lazy / priority，不能用 build-time enhanced；864 张 253MB 卡图也不适合逐张构建期转码。
- app-owned 默认 UI overlay（frame/banner/plaque/border）属构建期已知资源：复制 46 张到 `src/lib/data/card-ui/`，
  `card-images.ts` 改用相对 `./card-ui/...` glob + `query:{enhanced:true}`，仍以 `/images/...` 逻辑 URL 作为 Map key；
  `static/images/card_*` 保留作 manifest / smoke / 回退 URL，未删除、未改 manifest 与 mods.spec 断言。
- 未命中映射的 mod 自定义 frame 继续走 `uiImage` snippet 的 `<img>` 回退；`CardThumb` / `CardRow` / 两个页面均未再改。
