## 修复：全局 `a` 规则压过 Tailwind 工具类（cascade layer 问题）

### 现象
header-inner 与 tool-card 的 `<a>` 加了 `no-underline hover:no-underline` 仍被下划线覆盖
（DevTools 显示 `.no-underline` 被划掉，hover 出现 `text-decoration: underline`）。

### 根因
`src/routes/layout.css` 底部的全局 `a {…}` / `a:hover { text-decoration: underline }` 写在
`@import 'tailwindcss'` 之后、**未包进任何 `@layer`**。Tailwind v4 建立
`@layer theme,base,components,utilities`；**未分层的 author 样式凌驾于所有分层样式之上**，
所以这两个全局规则（unlayered）压过了 `@layer utilities` 里的 `.no-underline` / `hover:no-underline`。

### 修复
把全局 `a` / `a:hover` 包进 `@layer base { … }`。这样：
- 普通正文链接仍保留 hover 下划线（base 层定义）；
- 组件工具类（`no-underline`、`text-gold`、`hover:text-ink` 等，utilities 层）能正确覆盖
  base 层默认——utilities > base 的层序保证组件样式胜出。

### 验证
- `pnpm check`：0 errors（6 warnings 均为 paraglide 生成的 messages 文件缺失，与本次无关）。
- 已排除其它未分层 `a` 规则：仅 `layout.css` 一处全局；其余 `hover:underline` 均是组件内
  有意的正文链接 hover；`power/[id]/+page.svelte` 的 `.crumbs a` / `.origin a` 是 scoped 样式，
  只作用于面包屑，不影响 header / tool-card。
- dev server 已重启于 5173（`pnpm dev`），可目视确认 header 链接与 /tools 卡片无下划线。

`wiki-icon-label`。

### 根因
`WikiText.svelte` 的 `captureLabel` 用 `/^\s*([\p{L}]+)/u` 抓图标后的标签：中文没有空格，
会把整句「易伤是玩家和敌人……」一次吞掉，`wikiTerm(label) === term` 必然失败；
标签没被消费，剩余文本又被 `splitTerms` 的 `TERM_PATTERN` 二次命中「易伤」并自动加图标 → 重复。
英文多词名（Double Damage / Strike Dummy）同理：`sameLabel` 还额外要求 `term` 存在，
无 tooltip 的实体永远不会消费标签。

### 改动
- `WikiText.svelte`：`captureLabel` 改为基于 `WIKI_TERM_NAMES` 的最长前缀匹配（首字符过滤 +
  ASCII 边界检查），并用 `compactName` 归一化、term 对象身份、`wikiEntity().id` 三重校验确认
  「候选标签 == 图标实体」；命中后消费标签，图标 token 直接带 `iconLabel`，只生成一个元素。
- `power-wiki.ts`：`wikiRelic` 新增 `RELIC_ICONS_BY_ID`，先按 id 精确查再退回 compactName，
  解决 `Strike Dummy` / `Strike Dummy???`（FakeStrikeDummy）压缩同名冲突导致 `captureAlias` 失配。
- `WikiIcon.svelte`：把 `<img>` 与 `{#if label}` 的模板空白贴紧，消除图标与 label 之间的
  游离空格文本节点（顺带修好 4 个 CardDescription / GameText 组件测试的 textContent 断言）。
- 新增回归：`WikiText.svelte.spec.ts` 2 例（中文易伤 / 英文多词标签各只出 1 个元素且同时含
  `wiki-icon-link` + `wiki-icon-label`），`wiki-entities.spec.ts` 1 例（id 优先解析遗物）。

### 验证
- `pnpm exec vitest run`：25 文件 / 179 测试全过；`pnpm check` 0/0；
  `svelte-autofixer` 对 WikiText / WikiIcon 均无 issues。
- zh SSR `/power/VulnerablePower`（Cookie `sts2_mod_wiki_locale=zhs`）：
  `.wiki-card-link` 从 145 → 136，相邻重复对 9 → 0；首个元素为单个
  `wiki-card-link wiki-term`，内含 1 个 `wiki-icon-link` + 1 个 `wiki-icon-label`（易伤）。
- Chrome 浏览器重载目视确认：首段只剩一个心形图标 + 「易伤是……」。

### 注意
- 取 zh SSR 必须带 `Cookie: sts2_mod_wiki_locale=zhs`（paraglide cookie 名见
  `src/lib/paraglide/runtime.js`），否则 curl 拿到英文页。

  `<span class="wiki-card-link wiki-term">`，断言别写死 `wiki-term`。

## wikiIntro 中文实体异常排查（VulnerablePower）

- 文案源：`static/mods/sts2/localization/{zhs,eng}/powers.json` 的
  `VULNERABLE_POWER.wikiIntro`（无生成脚本，静态翻译文本）；链路
  `powerWikiIntro()` → `WikiIntro` → `introParagraph` → `WikiText.text`，
  不经 `parseGameText` 的 BBCode AST。
- 结论：不是 AST/中文分词/混排识别问题。正则 `(?<![\w])(...)(?![\w])` 对
  中文引号、中文紧邻英文均可匹配；`易伤`、页面下方 `痛击/主宰/纸蛙` 均正常成链。
- 三项根因：
  1. `重击` 是错译，官方 `BASH.title=痛击`，名称索引里 `重击` 计数 0 → 纯文本。
  2. `巨像` 中文同名：`COLOSSUS.title`(卡牌) 与 `COLOSSUS_POWER.title`(能力)，
     `wikiEntryFor` 先查 `WIKI_ENTITY_ALIASES`（power 中文别名）→ 链到
     `/power/ColossusPower`；英文页 `Colossus` 同样错链，属索引优先级缺陷。
  3. `Dominate`/`Paper Phrog` 未在翻译时替换为 `主宰`/`纸蛙`；
     `WikiText` 直接输出匹配到的原词，且 `wikiEntryFor` 固定 `resolvePowerReference(ref,'eng')`，
     不做 eng→zhs 显示名映射。
- 正确中文名：Bash=痛击(卡牌)、Colossus=巨像(卡牌 /cards/Colossus)、
  ColossusPower=巨像(能力 /power/ColossusPower)、Dominate=主宰(卡牌)、
  Paper Phrog=纸蛙(遗物)。
- 附带：`StS2 IconIronclad.png 铁甲战士` 渲染出空 `wiki-term` span + 纯文本角色名
  （中英页一致），角色图标数据缺失。
