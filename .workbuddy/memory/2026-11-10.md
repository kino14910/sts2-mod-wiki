# 2026-11-10

## 社区协作系统重构：第一步「游戏数据与 Wiki 内容分离」架构落地

依据 `docs/Spec STS2 Wiki 社区协作系统重构.md`，完成 Phase 1 基础 + §4 数据分离。

### 关键技术结论（后续阶段必须沿用）

- **SvelteKit 3 + adapter-cloudflare 8 不再在构建出的 Worker 里填充 `event.platform`**。
  Worker 模板只把 `env` 传给 `server.init()`；`event.platform` 仅在 dev emulator 存在。
  绑定必须从 `import { env } from 'cloudflare:workers'` 读取（`src/lib/server/wiki/db.ts`），
  且要在 `try/catch` 中访问——build/prerender 阶段该模块是桩，proxy 未初始化会抛错。
- **SvelteKit 3 的 `+page.server.ts` 返回值不会直接进 `data`**，只作为 `+page.ts`
  universal load 的 `data` 参数；必须在 universal load 里 `...data` 转发，否则 `PageProps` 缺少字段。
- `$app/environment` 在 v3 已废弃且无类型声明，改用 `$app/env` 的 `browser` / `building`。
- **同时存在 universal + server load 时 prerender 页面禁止访问 `url.searchParams`**。
  `/cards` 列表页组件改为 `browser ? page.url.searchParams : new URLSearchParams()`，
  筛选参数由已有的 `afterNavigate` 在 hydration 后补齐。
- prerender 爬虫会因 static/mods 缺失的图片（7 个 404）失败；在 `vite.config.ts` 的
  `sveltekit({ prerender: { handleHttpError } })` 中只放行 `/mods/` 下的 404，其余仍 fail。

### 已落盘结构

- `src/lib/entities.ts`：`entity_type + entity_id` 稳定标识（`card:Abrasive`）、key/slug/href/校验。
- `src/lib/data/entities.ts`：只读游戏数据注册表（CARDS/RELICS/POTIONS/POWERS/KEYWORDS）。
- `src/lib/data/wiki-seed.ts`：静态 wiki JSON 作为 seed 基线（不是线上数据源）。
- `src/lib/server/wiki/`：types / db / repository / sections / page-service。
  `loadWikiPage(db, ref)` 组合「JSON 游戏数据 + D1 Wiki 区段」，D1 不可用时回退 seed。
  现有 wiki 页以单个 `document` 结构化区段导入，Phase 2 再拆成 description/mechanics/strategy/history。
- `src/lib/server/auth/`：可替换 AuthProvider 接口（默认未注册 → 全部写操作拒绝）+ 角色权限表。
- `migrations/0001_wiki_foundation.sql`（7 表 + 索引）、`0002_seed_wiki.sql`
  （由 `scripts/gen-wiki-seed-sql.mjs` 生成）。
- `wrangler.jsonc` 增加 `DB` 绑定；`database_id` 是占位符，远端需先 `wrangler d1 create`。
- SSG：`/cards /relics /potions /powers /keywords`；SSR：三个详情页（各自 `+page.server.ts`）。

### 验证结果

- `pnpm check` 0 error；`vitest --run` 64/64；`pnpm build` 成功且生成 5 个 `*.html`。
- `wrangler d1 migrations apply sts2-mod-wiki --local` 两个迁移成功；唯一约束/FK 生效。
- `wrangler dev` 与 `vite dev` 下 `/relic/CrackedCore` 均返回 `source:"d1"`；
  直接改 D1 的 revision 内容后无需重新构建，SSR 页面立即显示新内容。

### 注意事项 / 未完成

- 本轮**未实现**编辑 UI、Proposal 审核、Revision 历史 UI、评论、真实认证接入、API 路由。
- 工作区有**外部并发改动**：`src/lib/components/WikiIcon.svelte`（原有未提交修改）、
  `src/lib/data/power-wiki.json`（zh→en）与新增 `power-wiki.zh.json`，均未由本次改动产生，不要覆盖。
  种子 SQL 已按当前英文版 `power-wiki.json` 重新生成；本地 D1 仍是较早的中文种子

## 第二轮：对齐更新版 spec（Mod 自带 Wiki 内容源）

用户更新了 spec，新增 §5「Mod Wiki 内容源与同步机制」、§6 两张来源表、§4.3「D1 唯一运行时来源」。

### 关键架构决策（后续阶段必须沿用）

- **运行时不再回退静态 wiki JSON**。`loadWikiPage` / `loadModWikiPage` 只读 D1；
  D1 不可用 → 空区段（不再读 `wiki-seed.ts`）。静态 JSON 仅由构建期 `0002_seed_wiki.sql`
  一次性导入，Revision 标 `source_type='mod_seed'` + `source_reference`。
  例外：`power-wiki.ts` 的 `WIKI_TERMS`/`WIKI_ENTRIES` 是渲染用 Token 字典，保留静态加载。
- `src/lib/wiki-document.ts` 只放 `WikiDocument`/`parseWikiDocument`（纯类型 + 校验，不 import JSON），
  供运行时引用；`src/lib/data/wiki-seed.ts` 仅用于构建/测试。
- **Mod 目录沿用现有 `static/mods/{modId}/`**，新增 `wiki/manifest.json` + `*.md`。
  spec 建议的 `src/lib/mods/{modId}` 在本项目不存在，不要另起一套。
  页面身份来自 manifest 的 `modId + slug`，**不来自文件路径**；一个 md = 一个 Section。
- `wiki_pages` 用部分唯一索引：`(entity_type,entity_id)`、`(slug) WHERE page_type='entity'`、
  `(mod_id,slug) WHERE page_type='mod'`，实现「不同 Mod 可同名 slug」。
- **Node 22 `--experimental-strip-types` 可直接 import 无依赖的 `.ts` 模块**（需显式 `.ts` 扩展名）。
  纯决策引擎 `src/lib/server/wiki/source-sync-service.ts` 与 `validation.ts` 因此可被
  vitest 与 `scripts/mod-wiki/*.mjs` 共用，无需 tsx/vite-node。`#lib` 别名在 Node 下不可用，
  所以这些纯模块不能 import 任何带别名的文件。
- **独立脚本通过 `getPlatformProxy({ persist: { path: '.wrangler/state/v3' } })` 拿本地 D1**，
  与 `wrangler d1 migrations apply --local` 共用同一状态目录。远端无编程 API，
  `--emit-initial --emit-sql <file>` 可对全新 D1 生成完整初始导入 SQL（已在隔离 D1 验证）。
- 三方决策顺序：NEW → E(文件删除) → B(incoming==base) → A(current==base) → D(incoming==current) → C。
  C 只建 `wiki_source_updates` 候选，绝不自动发布；B/A/D 会撤回过期候选。

### 验证结论

- `pnpm check` 0 error、`vitest --run` 99/99、`pnpm build` 成功（5 个 SSG 页）。
- 本地 D1 重置后 `0001`(29 条) + `0002`(9 条) 迁移通过；A/B/C/D/E 五种同步情况端到端验证通过，
  重复同步不产生重复 Revision；E 保留正式 Revision 并标记来源 `deleted`。
- `wrangler dev`：`/mods/sts2/wiki/index` 与嵌套 slug 均 200，D1 改内容后 SSR 立即变化；
  Token 渲染保留（`<strong>` / `wiki-upgraded` / Power 图标 / 卡牌图标）；
  `/api/admin/wiki/sources` 未认证返回 403。

### 未完成

- `wiki_source_updates` 的人工批准/拒绝/合并（生成 `mod_update` Revision + 更新来源快照）尚未实现，
  目前只有检测、冲突候选与只读管理 API。
- Phase 3–6 全部未做：编辑 UI、Proposal、Revision 历史/Diff/恢复、评论、真实认证接入。
- `member` 才能评论（spec §9 改为必须登录），当前权限表仍给 member `comment:create`，一致。
- 工作区外部并发改动（`WikiIcon.svelte` / `power-wiki.json` / `power-wiki.zh.json`）仍未由本项目改动产生。

  只存 `key` + `groups{kind, partition, refs[{type,id,variant?}]}`；39 条引用
  （28 card / 4 relic / 2 potion / 5 power），分组为 1 + 2 个 section、16 个 group。
  `type/id` 与 `src/lib/entities.ts` 的 EntityRef 一致；`MadScience` 用 `variant: "sapping"` 保留形态标记。
- `src/lib/data/power-wiki.json` 和 `power-wiki.zh.json` 只留
  `title/stackType/text/order/effectsImmune`，叙述内容逐字段保持不变。
- 新增 `static/mods/sts2/localization/{eng,zhs}/wiki.json`（各 17 键）承载
  section/group/partition/variant 标签；键集合严格一一对应，中文沿用原 wiki 文案
  （如「施加于敌人」「药剂」「任意」「能力」）。实体名称/描述仍来自
  `localization/{eng,zhs}/{cards,relics,potions,powers}.json`，变量/卡池来自
  `cards.json` / `relics.json` / `potions.json`。

  `docs/mod-manifest.md` 新增「Buff 页面的来源 / 交互引用」章节。

  en/zh 渲染结构一致、wiki 文件无硬编码字段、标签键集合一致。

  旧 `tooltip-container` / `images_thumb_StS2...` 硬编码 HTML 在响应中已为 0。

  `.svelte-kit/cloudflare` 会被沙箱 safe-delete 拦截而失败；先停服务再 `pnpm build`。
